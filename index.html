Technical solution

Next.js + Node.js cloud architecture

One product, modular domains, API-first backend, cloud-ready database mapped 1:1 to the office ownership rules from the business logic pack.

Stack

Recommended technology choices

Frontend

Next.js (App Router)

Role-based UI, server components for lists/reports, client islands for POS / dense forms. TypeScript throughout.

Backend

Node.js API

Dedicated NestJS or Fastify service (or Next Route Handlers early, extract when domains grow). Domain modules mirror office desks.

Data

PostgreSQL

Replace Access MDBs. Prisma or Drizzle ORM. Multi-company via tenant / company id. Object storage for dossiers & PDFs.

Auth

OIDC / Auth.js or Clerk/WorkOS. Company membership, role permissions per module (replacing CONFIG.MDB users).

Jobs & reports

Queue (BullMQ / SQS) for payroll import, budget sync, PDF generation. PDF engine replaces Crystal staging.

Hosting

Vercel or container for Next; API + workers on containers (ECS/Cloud Run); managed Postgres; S3-compatible files.

Cross-cutting

  • notices (avis)

Migration strategy: dual-run period with ETL from company MDBs to Postgres, keyed by company + NOITEM. Start with contracts + bids, then extras, then costs, then yard.

Enforcing rules in code

Business logic as services

AwardService

Rejects if bid already linked; allocates number series; creates contract; emits ContractAwarded.

ExtraApprovalService

Updates flags; letter generation can flip Approuvé / Rappel; locks baseline amount rules.

BudgetSyncService

On extras-session close: sum A/B rows, then upsert budgets (sign convention). Idempotent.

JobCostTransferService

Only if G/L job-cost eligible; set provenance module; A/R path requires confirmation flag.

InvoiceService

Sole creator of progressive invoices. Extra reprint endpoints are read-only against existing invoices.

WipService

Period snapshots; never callable from yard domain.
